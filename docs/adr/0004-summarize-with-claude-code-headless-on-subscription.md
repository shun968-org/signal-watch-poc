# ADR-0004: 変更内容の要約に、サブスクリプション認証の Claude Code ヘッドレスモードを使う

- ステータス: 採用
- 日付: 2026-10-17
- 関連: ADR-0001、Notion 要件定義(REQ-017)・基本設計(F-10)

## コンテキスト

【変更】の通知に、変更の要点を短い文章で載せる(REQ-017)。要約は変更を検出したときだけ、1日数回・数百字程度行う。
利用者は Claude のサブスクリプション(Pro / Max など)を持っており、**従量課金など、サブスクリプションとは別に料金が発生する仕組みは使わない**ことが条件である。
巡回は GitHub Actions(ADR-0001)で動き、取得したページは公開情報(デジタル庁、公共データ利用規約)である。

### 検討した選択肢

| 案 | 却下理由 |
|---|---|
| Claude API を API キー(`ANTHROPIC_API_KEY`)で呼ぶ | 従量課金になり、サブスクリプションとは別に料金が発生する |
| anthropics/claude-code-action を使う | サブスクリプション認証に対応しているが、Issue・PR への応答を主にした Action で、巡回の Python 処理の途中で要約だけを得る用途には大きすぎる |
| 要約しない(抜粋とリンクだけ) | REQ-017 を満たさない |

## 決定

**変更内容の要約は、GitHub Actions 上で Claude Code のヘッドレスモード(`claude -p`)を、サブスクリプションの長期トークン(`claude setup-token` で発行し、Secret `CLAUDE_CODE_OAUTH_TOKEN` で渡す)で認証して実行する。モデルは Claude Opus 5.5(`claude-opus-5-5`)とする。**

判断の根拠:

1. **追加料金が発生しない。** OAuth トークンで認証すると、API の課金ではなくサブスクリプションの使用量として扱われる(Claude Code のドキュメント「GitHub Actions」「Authentication」)。
2. **安全に絞り込める。** ツールを無効(`--tools ""`)にし、会話を保存しない(`--no-session-persistence`)。ページの文章に指示が紛れていても、要約の文章を返す以外のことはできない。
3. **追加の依存が少ない。** Claude Code(npm パッケージ)を版を固定して入れ、Python から子プロセスとして呼ぶだけで済む。

## 結果

- **追加料金を防ぐ条件を守る必要がある。** Claude Code は `ANTHROPIC_API_KEY` などの API キーがあるとそちらを優先し、ヘッドレスモードでは必ず使う。そのため:
  - リポジトリの Secret とワークフローに API キーを置かない
  - 要約の子プロセスには API キー系・クラウド事業者系の環境変数を渡さない
  - 実行前に `claude auth status` で認証方式を確かめ、サブスクリプションでなければ要約しない
  - `--bare` を使わない(サブスクリプションのトークンを読まない)
  - claude.ai の追加使用量(usage credits)をオフにしておく(オンのときにヘッドレスモードが使うかは、ドキュメントで確認できなかった)
- 利用者がふだん使う Claude Code と使用量の枠を共有する。枠を使い切ったら要約は失敗する。
- トークンの有効期限は1年。切れたら要約は失敗するので、作り直して Secret を登録し直す。
- 要約に失敗・タイムアウトしても、要約なしで通知を送る(通知を止めない)。
- サブスクリプションの認証は「個人による通常の利用」を前提としている(Claude Code のドキュメント「Legal and compliance」)。個人の PoC として自分のリポジトリで使う範囲に留め、チームや組織の共有の仕組みに広げるときは API キー(従量課金)への切り替えを含めて見直す。
- Claude Code の版は固定する。上げるときは `watch.yml` の版を変える。
