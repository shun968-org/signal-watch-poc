# ADR-0001: GitHub Actions の定期実行で巡回し、スナップショットを Git にコミットして保存する

- ステータス: 採用
- 日付: 2026-10-13
- 関連: Notion 要件定義(REQ-002, REQ-008, REQ-009, REQ-010, REQ-011, REQ-016、非機能要件・制約条件)

## コンテキスト

少数(10件以下)の官公庁のお知らせページを定期的に取得し、前回との差分を検出して Slack に通知する PoC を作る。
個人開発であり、サーバの運用・費用はできるだけ持ちたくない。
取得結果と差分は履歴として残し(REQ-010)、後から参照できる必要がある(REQ-011)。
通知には要約だけを載せ、詳細な差分は別の画面へのリンクで見せる(REQ-016)。
対象サイトの都合上、取得は1時間に1回以下の頻度で足り、分単位の正確な起動は要らない。

### 検討した選択肢

| 案 | 却下理由 |
|---|---|
| ローカル PC の cron・常駐プロセス | PC を止めている間は監視も止まる。履歴の保存・閲覧の仕組みを別に用意する必要がある |
| クラウドのスケジューラ(Cloud Run Jobs、Lambda など) | アカウント・権限・費用の管理が PoC の規模に対して重い。差分の閲覧画面も別に要る |
| スナップショットをデータベースや外部ストレージに保存する | 差分の閲覧画面を自作する必要があり、PoC で検証したい部分(検出と提示)以外の作業が増える |

## 決定

**GitHub Actions の schedule で巡回処理を定期実行し、取得・抽出したスナップショットをこのリポジトリにコミットして保存する。
通知には変更行の要約と、そのコミットの差分画面へのリンクを載せる。**

判断の根拠:

1. **サーバが要らない。** 実行環境・ログ・シークレット管理(Slack の Webhook URL)を GitHub がまとめて提供する。
2. **履歴と差分の閲覧を自作しなくてよい。** コミット履歴がそのまま変更履歴になり、コミットの差分画面が詳細な差分表示になる。
3. **PoC の頻度に合っている。** 1時間に1回以下の取得なら、schedule の起動精度で足りる。

## 結果

- schedule は時刻どおりの起動が保証されず、混雑時には遅延・スキップがありうる。検出が遅れることは許容する。
- 60日間リポジトリに動きが無いと schedule が無効化される。スナップショットのコミットがあれば普段は問題にならないが、更新の少ない時期は注意が要る。
- 取得のたびにコミットが増え、リポジトリの容量が増え続ける。保存期間・古いスナップショットの扱いは未決(Notion 未決事項 #8)。
- リポジトリは public のため、スナップショットと差分は誰でも閲覧できる。取得元の利用規約が複製・公開を認めるページに限り、出典をリポジトリ上に明記する。
- 巡回処理によるコミットは、人のコミットと規約(Conventional Commits・commitlint)を揃えるか、ボット用のブランチ・規約を分けるかを基本設計で決める必要がある。
- 取得元は GitHub のランナーの IP になる。対象サイト側で海外 IP・データセンターからのアクセスが制限されている場合は取得できない。
